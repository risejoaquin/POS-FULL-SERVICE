# POS Versioning and Release Manifest Baseline

## Scope

PHASE 8C records the versioning and release manifest baseline after PHASE 8B. It is documentation and verification only. It does not create packages, installers, deployments or rollouts.

## Required evidence

- versioning and release manifest baseline documented
- PHASE 8B release artifact inventory prerequisite documented
- 400 tests passed source evidence documented
- 405 tests expected after versioning manifest verification documented
- semantic version format documented
- release channel documented
- build number source documented
- commit sha source documented
- artifact manifest template documented
- manifest checksum field documented
- manifest artifact path field documented
- manifest created at field documented
- manifest generated by field documented
- release notes version linkage documented
- rollback version linkage documented
- package version stamp checklist documented
- operator manifest review checklist documented

## Release version baseline

The release version must be recorded before packaging with this minimum structure:

```text
version: MAJOR.MINOR.PATCH
channel: dev | staging | production
build_number: CI or operator supplied immutable build number
commit_sha: source control commit hash for the release candidate
created_at_utc: UTC timestamp for manifest creation
generated_by: release operator or CI identity
```

## Artifact manifest baseline

The release manifest must link every release artifact to its version and checksum evidence:

```text
artifact_name
artifact_type
artifact_path
artifact_version
artifact_checksum_sha256
artifact_created_at_utc
artifact_source_commit_sha
```

## Safety boundaries

- No checkout behavior change
- No inventory mutation
- No production sync enablement
- No packaging execution
- No installer execution
- No deployment execution
- No public API behavior change
- No schema change
- No migrations
